# Stage 5: Inventive-Step Analysis

## Enter this stage when

- the user asks for stage 5
- the core feature set is fixed
- the case needs an authorization-oriented inventive-step main line

## Required baseline

- confirmed core-feature analysis
- current technical baseline
- confirmed Search Checkpoint B recheck results

## Task focus

- identify the closest prior-art route from checkpoint B at a technical-concept level
- identify distinguishing runtime features
- test common-knowledge risk, synergy, and additive-improvement logic
- identify whether any claimed effect actually depends on features not yet in the main chain

## Deliverable

- inventive-step report with main line, weak lines, and narrowing suggestions

## Guardrails

- do not treat every parameter preference as inventive by default
- if checkpoint B is thin or stale, state that the inventive-step view is provisional
- if the strongest line is weak, say so directly

## Stop rule

Stop after the inventive-step report and wait for confirmation before the final disclosure.

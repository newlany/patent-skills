# Stage 9: Background Drafting

## Enter this stage when

- the user asks for stage 9
- the user asks for 背景技术
- the claim baseline and technical route are fixed

## Required baseline

- confirmed final disclosure
- confirmed claim baseline

## Task focus

- describe the technical scene and existing technical routes objectively
- describe the observable prior-art phenomena or resulting limitations in actual use
- if the prior art already covers an upstream route, acknowledge that route fairly
- align the stated background phenomena with the issue later handled by the adopted method chain

## Writing defaults

- write the background in the order `technical scene -> conventional route -> use context -> observable phenomenon`
- by default, do not explain why the prior-art problem or phenomenon arises; move that causal analysis to invention content
- by default, let the ending land on what phenomenon exists in the prior art, rather than on a solution-oriented transition
- do not pre-state the invention's solution, key means, or step chain in background
- keep the tone objective; background should not read like a disguised inventive-step argument
- if the user asks to reduce AI-like tone, avoid long chained sentences and dense `、` lists; use shorter, cleaner sentences while keeping specification style

## Deliverable

- background section of the specification

## Guardrails

- do not pre-state the invention's solution
- do not put `申请人发现`-style cause attribution in background unless the user explicitly asks for that style
- do not write marketing language

## Stop rule

Stop after the background section and wait for confirmation before invention content.

# Stage 4: Core Feature Analysis

## Enter this stage when

- the user asks for stage 4
- the operative method boundary is fixed
- the case needs a claim-oriented minimum feature set

## Required baseline

- confirmed reconstructed disclosure
- confirmed method-boundary recommendation
- any confirmed narrowing direction from earlier stages
- confirmed Search Checkpoint A when the case is being prepared for inventive-step judgment or claim drafting

## Task focus

- extract the single core technical problem that the method should solve
- identify the key technical means, the necessary runtime features, and their causal sequence
- separate necessary features, preferred features, and implementation details
- decide which features belong in claim 1 and which should stay out
- prepare the re-search anchors for checkpoint B around the candidate claim-1 chain

## Deliverable

- structured claim-oriented feature analysis report that states the technical problem, the key technical means, the candidate claim-1 feature chain, and the checkpoint-B re-search anchors

## Guardrails

- avoid multiple parallel technical problems unless the user wants that
- tie every necessary feature to the problem it solves

## Stop rule

Stop after the feature analysis and wait for confirmation before inventive-step work. When the work is heading toward inventive-step analysis or claim drafting, recommend Search Checkpoint B before stage 5.

# Stage 1: Disclosure Analysis

## Enter this stage when

- the user asks for stage 1
- the original disclosure must be audited before drafting
- the case contains contradictions, missing facts, or unclear process logic

## Required baseline

- original disclosure files
- any inventor notes, issue lists, or internal analysis if available

## Task focus

- separate disclosed facts, reasonable technical completion points, and inventor-confirmation points
- identify missing parameters, devices, materials, data flows, step outputs, and test conditions
- identify contradictions, unsupported generalizations, ambiguity, and process-chain breaks
- identify whether the disclosure already mixes preconditions, runtime steps, and later updates
- extract the first-pass search anchors that will feed checkpoint A, such as scene words, effect words, structural anchors, and unusual technical constraints

## Deliverable

- disclosure analysis report
- issue list with impact and proposed repair path
- search-anchor summary for checkpoint A when the case is heading toward drafting or inventive-step work

## Guardrails

- do not repair the disclosure in this stage
- do not collapse multiple technical routes without saying so

## Stop rule

Stop after the analysis report and wait for confirmation before reconstruction. When the work is heading toward patentability-oriented reconstruction or claim drafting, recommend Search Checkpoint A before stage 2.

# Stage 3: Method-Boundary Alignment

## Enter this stage when

- the user asks for stage 3
- the disclosure or current draft confuses runtime steps with preconditions, offline preparation, or later updates
- the case includes pre-established libraries, models, rule bases, calibration data, templates, prior records, or accumulated experience data

## Required baseline

- confirmed reconstructed disclosure or equivalent stable technical baseline
- any current claim draft if available

## Task focus

- classify candidate operations into pre-established support, runtime step, or post-run update
- determine the operative runtime chain for claim 1
- decide which support resources should be recited only as the basis of a runtime step
- identify stale steps or overbroad steps that should be removed, merged, or relocated

## Deliverable

- method-boundary memo
- revised step chain recommendation for claim 1
- list of sections that must later be synchronized

## Guardrails

- do not leave a support-resource build step in the main method chain by default
- if a support resource remains in claim 1, its runtime function must be explicit

## Stop rule

Stop after the boundary memo and wait for confirmation before core-feature analysis or claim layout.

# Stage Checkpoints

For staged work, after every stage or mandatory search checkpoint, stop and wait for user confirmation.

## Mandatory prior-art checkpoints for drafting and inventive-step work

When the downstream goal is technical-solution reconstruction, inventive-step judgment, or claim drafting, do not go straight from stage 1 to stage 2 or from stage 4 to stage 5.

Use these two checkpoints:

1. Search Checkpoint A
   - timing: after stage 1 and before stage 2
   - purpose: map the current-art baseline, the closest routes, and the reconstruction directions worth keeping
   - minimum output: closest references, novelty or inventive-step pressure, and reconstruction-direction advice
2. Search Checkpoint B
   - timing: after stage 4 and before stage 5
   - purpose: re-search the reconstructed scheme or candidate claim-1 chain and test whether the intended inventive-step main line still holds
   - minimum output: closest reference to the reconstructed scheme, combination or common-knowledge risk, and a go or revise recommendation for stage 5

Use this handoff pattern:

1. completed deliverable
2. key assumptions or unresolved points
3. recommended next stage
4. direct confirmation request

For stage 1, the recommended next step should normally be Search Checkpoint A when the work is heading toward drafting.
For stage 4, the recommended next step should normally be Search Checkpoint B when the work is heading toward inventive-step analysis or claim drafting.

Do not silently continue to the next stage.

If the user asks for revisions, revise the current stage first and ask for confirmation again before continuing.
If the user explicitly asks for uninterrupted execution, keep the same handoff structure between stages, but treat the confirmation as pre-authorized.

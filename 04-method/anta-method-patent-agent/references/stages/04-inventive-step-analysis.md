# Stage 4: Inventive-Step Analysis

## Enter this stage when

- the user asks for stage 4
- the core feature set is fixed
- the case needs an authorization-oriented inventive-step main line

## Required baseline

- confirmed core-feature analysis
- current disclosure baseline
- any known prior-art routes if available

## Task focus

- identify the closest prior-art route at a technical-concept level
- identify distinguishing features
- test common-knowledge risk, synergy, and additive-improvement logic
- tell later stages which line is strong, weak, or needs disclosure back-fill

## Deliverable

- inventive-step report with main line, weak lines, disclosure gaps, and narrowing suggestions

## Guardrails

- do not treat every parameter preference as inventive by default
- if the strongest line is weak, say so directly

## Stop rule

Stop after the inventive-step report and wait for confirmation before the final disclosure.

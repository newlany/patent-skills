# Patent Topic Deep Research Methodology

## Core View

Patent深度研究不等于“写得更长”。它等于六件事同时成立：

1. 先锁定研究边界，而不是先堆资料。
2. 先搭问题树，而不是先写结论。
3. 先做来源分级，而不是把法条、案例、评论混写。
4. 通过多轮检索补齐缺口，而不是一轮搜完就收束。
5. 显式区分事实、规则、判断、建议和不确定性。
6. 最终输出不仅有答案，还能留下可复用的方法、清单和模板。

## 1. 先过“研究框架闸门”

在真正检索之前，先固定以下内容：

1. `研究主题`：到底研究什么问题，不要只写宽泛领域。
2. `法域`：中国大陆、美国、欧洲、PCT 或其他。
3. `程序阶段`：申请审查、复审无效、侵权诉讼、确权诉讼、培训研究等。
4. `核验日期`：所有“截至目前”“最新”“当前口径”都要落到绝对日期。
5. `输出形态`：长篇研究报告、培训底稿、争点备忘录、趋势综述、可改写模板等。
6. `纳入范围`：哪些问题一定研究。
7. `排除范围`：哪些问题明确不展开，防止主题膨胀。

如果以上信息不完整，先做最小必要假设，并在成稿中写明假设。

## 2. 先建立来源等级

使用以下通用层级。必要时可按课题微调，但不要反转优先顺序。

| 等级 | 来源类型 | 主要用途 |
| --- | --- | --- |
| A | 法律、实施细则、司法解释、审查指南、国家机关正式公告、官方解读 | 确定规范基线、现行规则、版本变化 |
| A- | 最高人民法院知识产权法庭官方案例分析、裁判要旨、入库案例、指导性或典型案例、官方答问、CNIPA 典型案例 | 提炼裁判规则、审查口径、程序要求 |
| B+ | 本地专利知识库、专题研究、裁判规则索引、内部知识沉淀 | 快速建图、发现子议题、交叉核验、沉淀复用结构 |
| B | 官方 deep research 方法说明、学术论文、研究方法资料 | 仅用于方法论、质量控制和研究协议设计 |
| C | 律所文章、博客、评论、数据库摘要、新闻 | 只用于发现问题、补充线索；关键结论必须回到更高等级来源 |

使用规则：

1. A 与 A- 是正文结论的核心依据。
2. B+ 是高价值导航层，不应直接替代 A 与 A-。
3. B 只解决“如何研究”，不替代专利法上的实体依据。
4. C 不能单独承载高风险结论。

## 3. 先搭通用问题树，再按专题加枝叶

任何专利专题深度研究，至少先拆成八层：

1. `问题定位层`：主题到底是什么，相关概念边界在哪里。
2. `规范基础层`：法条、指南、司法解释、官方解读如何构成规则骨架。
3. `规则结构层`：判断步骤、构成要件、认定路径、证明门槛是什么。
4. `证据与程序层`：什么材料能证明，谁负担举证，程序如何保障。
5. `边界与例外层`：最容易混淆、最容易被偷换的问题是什么。
6. `案例集群层`：过去几年最有代表性的案例如何分组。
7. `趋势层`：最近一至两年是否出现新指南、新解释、新案例信号。
8. `实务层`：对撰写、答复、无效、诉讼、培训、知识管理分别有什么启示。

### 专题加枝模板

#### 创造性

在通用问题树之外，额外展开：

1. 最接近现有技术如何选。
2. 区别技术特征如何识别。
3. 发明实际解决的技术问题如何界定。
4. 技术启示或改进动机如何证明。
5. 公知常识与补充实验数据如何进入创造性判断。
6. 新技术领域、场景创新、AI、通信、中药、医疗器械等的细化边界。

#### 公知常识

在通用问题树之外，额外展开：

1. 公知常识与现有技术、常规技术手段、技术启示的关系。
2. 何种证据可以证明公知常识，证明强度如何分层。
3. 主张方的举证责任与程序告知要求。
4. 领域成熟度和申请日前时间状态如何影响认定。
5. 公知常识如何进入创造性之外的权利要求解释、权属或侵权场景。

#### 功能性特征

在通用问题树之外，额外展开：

1. 功能性表述、功能性限定、功能性特征如何区分。
2. 授权或确权阶段的支持性、清楚性风险如何发生。
3. 侵权阶段如何完成入口识别、内容还原和比对适用。
4. 实用新型、多使用环境、混合术语等特殊场景。
5. 撰写、无效攻击、侵权诉讼中的操作规则。

#### 第26条第3款与第4款

在通用问题树之外，额外展开：

1. 充分公开、支持、清楚、简要如何拆分。
2. 说明书公开与权利要求划界如何联动。
3. 参数、公式、配方、实验数据、算法流程如何影响第26条判断。
4. 申请、复审无效、侵权阶段的表达重点差异。
5. 机械、化学、医药、软件领域的高风险模式差异。

#### 侵权判定

在通用问题树之外，额外展开：

1. 权利要求解释路径。
2. 全面覆盖原则与等同原则。
3. 功能性特征、数值范围、使用环境等特殊解释问题。
4. 被诉技术方案的认定与取证。
5. 现有技术抗辩、先用权、合法来源、确认不侵权等抗辩结构。
6. 程序协同、损害赔偿与趋势问题。

## 4. 用“三轮检索闭环”代替“一轮搜完”

### 第一轮：建图

目标不是立刻下结论，而是找出：

1. 核心规范文本。
2. 官方解读或正式说明。
3. 高价值案例群。
4. 本地知识库中已沉淀的相关专题、索引和速查材料。
5. 当前仍然模糊的缺口。

### 第二轮：补缺

围绕缺口定向补查：

1. 最新修订、最新公告、最新官方页面。
2. 关键边界案例。
3. 容易被混同的相邻制度。
4. 技术领域或程序阶段的特殊分化。

### 第三轮：校冲突

只在以下情形启动第三轮：

1. 不同来源的日期不一致。
2. 规范与案例口径看似冲突。
3. 二级材料与一级材料不一致。
4. 结论仍依赖单一来源。
5. 用户明确要求“最新”“最权威”或高风险准确性。

## 5. 搜索时保留“缺口意识”

每读完一组材料，都追问：

1. 这个材料回答了什么。
2. 这个材料没有回答什么。
3. 这份材料处在哪个来源等级。
4. 这份材料适用于哪个程序阶段和时间点。
5. 这个结论是否还需要官方页面或新案例补证。

不要把“命中了一篇看起来很像答案的文章”误当成研究结束。

## 6. 写作时强制打标签

至少区分以下五类内容：

1. `规范事实`：法条、指南、司法解释、官方解读明确写出的内容。
2. `裁判规则`：官方案例分析、裁判要旨、典型案例中可稳定提炼出的规则。
3. `研究判断`：在多源交叉后形成的归纳，不是某一条文的原句。
4. `实务建议`：面向撰写、答复、无效、诉讼或培训的操作性建议。
5. `趋势观察`：基于近年更新、征求意见稿、连续案例变化作出的前瞻性判断。

补充标签：

1. `不确定`：材料不足，暂不能下稳定结论。
2. `待核验`：已发现线索，但尚未回到高等级来源。
3. `仅作发现用途`：来自评论或数据库摘要，不作为正文核心依据。

## 7. 强制保留来源映射

每个非琐碎结论尽量保留：

1. 来源编号。
2. 来源机构。
3. 来源日期。
4. 来源等级。
5. 该来源回答的是规则、案例、趋势还是方法。

长文最容易失败的地方不是没搜到材料，而是写到后面忘记“哪一句来自哪里”。

## 8. 对时间敏感问题必须写绝对日期

以下内容一律写绝对日期，不要只写“目前”“现在”“最新”：

1. 现行法版本。
2. 指南修订生效时间。
3. 官方解读发布时间。
4. 新案例发布时间。
5. 征求意见稿发布日期。
6. 你的核验截止日期。

## 9. 留下可复用结构

好的专题研究最终应留下至少一种复用资产：

1. 关键争点速查表。
2. 研究流程模板。
3. 实务检查清单。
4. 可直接改写的答复模块。
5. 资料分级与可信度说明。

如果只留下长篇正文，没有复用结构，研究价值会大幅下降。

## 10. 常见错误

以下做法应主动避免：

1. 先写结论，再回头找法源拼贴。
2. 把征求意见稿、趋势材料写成现行法。
3. 把本地二次整理材料写成一级规范。
4. 把“研究判断”伪装成“明文规则”。
5. 只堆来源，不覆盖主要分歧点。
6. 只做一次检索，不做补缺和回查。
7. 忽略法域、程序阶段和时间边界。
8. 不写边界与不确定性说明。
9. 不留清单、模板、速查表等复用产物。

## 11. 完稿前自问五个问题

1. 每个核心结论能否回到来源。
2. 是否覆盖了规范、案例、证据、边界和趋势五层。
3. 是否把事实、规则、判断和建议拆开写了。
4. 是否对时间敏感点给出了绝对日期。
5. 这份成果能否直接服务后续案件、培训或知识库更新。

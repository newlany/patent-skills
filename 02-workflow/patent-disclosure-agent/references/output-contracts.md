# 技术交底分析输出契约

三份工作稿应当形成一套可连续复用的分析包。

## 统一要求

- 所有结论优先基于交底书记载内容。
- 必须区分 `交底书明确记载`、`推断`、`信息缺失`。
- 问题定位优先使用步骤编号、章节标题、附图编号和原句片段。
- 保持术语、公式符号、图号、步骤号前后一致。

## 各文件角色

### `01_技术交底分析报告.md`

- 建立技术背景、问题、核心方案、技术逻辑链

### `02_技术交底逻辑重构与缺陷审查报告.md`

- 审查逻辑断点、参数缺失、术语不一致、支撑风险和回退层级

### `03_需要发明人补充说明的问题清单.md`

- 把前两份文档暴露出的缺口转化为可直接答复的问题

## 交付关系

- `02` 必须建立在 `01` 的技术主线之上
- `03` 必须引用并吸收 `01` 和 `02` 暴露的问题
- 导出 `.docx` 时，`01` 到 `03` 的口径必须一致

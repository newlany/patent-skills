# OA Output Contract

Every stage should produce a deliverable that a later stage can reuse without re-reading the entire file set.

## Standard stage handoff

When returning a stage result, include:

1. stage conclusion
2. basis and source layer
3. current baseline used
4. state updates or state items intentionally left unfixed
5. unresolved risks or assumptions
6. next recommended stage or confirmation checkpoint

## Source labeling

Label key points by source:

- application
- office action
- D1
- Dx
- common knowledge

## Baseline rules

- Separate preliminary difference analysis from final distinguishing features.
- Separate the current effective claim set from any superseded claim set.
- Separate factual findings from strategic judgments awaiting confirmation.
- If no live state item changes in a stage, say so explicitly.

## Writing rules

- Give the conclusion first, then the basis.
- Do not invent effects, mechanisms, or parameter meaning.
- Keep the current effective claims, distinguishing features, technical problem, and final draft mutually consistent.
- Label weaknesses precisely: disclosure error, technical problem error, technical teaching error, overbroad common knowledge, or hindsight reconstruction.

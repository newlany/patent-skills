# Seven-Rule Check

Run these rules only after the current effective claim set is fixed. Use them as a chain-break diagnosis for Article 22.3, not as seven equal paragraphs.

## Required inputs

- current effective claim set
- examiner Article 22.3 chain
- verified D1 and Dx findings
- final distinguishing features
- specification-supported technical effects
- confirmed actual technical problem

## The seven rules

| Rule | Core question | Useful rebuttal signal |
| --- | --- | --- |
| 1. Problem integrity | Is the actual technical problem free of hindsight and solution wording? | The problem is written too broadly, too narrowly, or as the distinguishing feature itself. |
| 2. D1 starting point | Does D1 objectively face the same technical problem? | D1 lacks the defect, need, or improvement direction that would start the modification. |
| 3. Dx disclosure | Does Dx truly disclose the cited technical means? | The examiner relies on inference, optional possibility, or a feature not directly disclosed. |
| 4. Same function | Does the Dx means serve the same or close function? | The similar means solves a different problem or works for a different effect in Dx. |
| 5. Combination fit | Can D1 and Dx be combined without changing the route or mechanism? | The combination requires structural redesign, control-flow change, or a different working principle. |
| 6. Predictability | Would the effect be predictable before the filing date? | The result is not reasonably foreseeable, or the route lacks reasonable success expectation. |
| 7. Direct obtainability | Would the claimed solution be directly obtainable by routine work? | The examiner needs selective extraction, multiple assumptions, or hindsight reconstruction. |

## Distinguishing-feature filters

Before running the seven rules, test the final distinguishing features with three filters:

1. Claim construction: the feature must be limited by the claim, or reasonably explained by the specification without rewriting the claim.
2. Prior-art disclosure: the feature is not disclosed unless the prior art directly and unambiguously contains it.
3. Function calibration: an apparent counterpart counts only when its role in the prior art is the same as, or close to, its role in the claimed solution.

If several features are tightly connected and jointly solve one concrete problem, consider them together. If they independently solve different problems, analyze them separately.

## Actual-technical-problem tests

Use these checks before confirming the problem wording:

- It is based on the effects of the final distinguishing features.
- It does not include the distinguishing feature or hint at the solution.
- It is more concrete than "optimize structure" or "provide another option".
- It does not import an unsupported use scenario, performance target, or advantage.
- If one feature has several supported effects, the problem does not ignore the effects that matter to technical teaching.
- If a feature does not contribute to solving the problem, label it as scope-only or support-only instead of making it the creative anchor.

## Chain-break labels

Label each useful finding with one of these labels so the final draft stays sharp:

- disclosure error
- distinguishing-feature error
- technical-problem error
- teaching error
- common-knowledge proof gap
- combination obstacle
- no reasonable success expectation
- hindsight reconstruction

## Ranking rule

Do not give equal weight to every rule. Mark each rule as:

- main point
- support point
- not useful

Prefer a main point that attacks the earliest strong break in the examiner's chain. Usually, a problem-definition error or same-function teaching error is stronger than a generic statement that the invention has advantages.

## Drafting skeleton

Use this order for near-final Article 22.3 paragraphs:

1. State the conclusion that the rejection cannot be accepted.
2. Identify the final distinguishing features for the current effective claim.
3. Tie each distinguishing feature to a supported technical effect.
4. Define the actual technical problem without solution wording.
5. Explain why D1 does not create the same improvement target, if applicable.
6. Explain why Dx or common knowledge does not provide the same-function teaching.
7. Explain any combination obstacle or lack of reasonable success expectation.
8. Close with the conclusion that the claimed solution is not obvious to the skilled person.

## Guardrails

- Do not write distinguishing features into the technical problem.
- Do not apply the rules to a superseded pre-amendment claim set.
- If a rule is weak, say so directly instead of padding the draft.
- Do not use "the prior art discloses a similar structure" as a shortcut for teaching or motivation.
- Do not rely on dense lists of advantages unless each advantage is tied to a final distinguishing feature.

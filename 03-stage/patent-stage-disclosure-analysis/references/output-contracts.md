# 技术交底分析输出契约

三份工作稿应当形成一套可连续复用的分析包。

## 统一要求

- 所有结论优先基于交底书记载内容。
- 必须区分 `交底书明确记载`、`推断`、`信息缺失`。
- 问题定位优先使用步骤编号、章节标题、附图编号和原句片段。
- 保持术语、公式符号、图号、步骤号前后一致。
- 如果分析包会继续进入撰写 workflow，允许并鼓励在 `01` 与 `02` 之间插入首轮查新，但必须说明哪些判断来自交底本身，哪些来自现有技术对比。

## 各文件角色

### `01_技术交底分析报告.md`

- 建立技术背景、问题、核心方案、技术逻辑链

### `02_技术交底逻辑重构与缺陷审查报告.md`

- 审查逻辑断点、参数缺失、术语不一致、支撑风险和回退层级
- 如果已有首轮查新结果，还要吸收最近现有技术造成的重构方向和收窄建议

### `03_需要发明人补充说明的问题清单.md`

- 把前两份文档暴露出的缺口转化为可直接答复的问题
- 如果查新暴露出区别点不清或事实支撑不足，也要把这些点转化为可追问问题

## 交付关系

- `02` 必须建立在 `01` 的技术主线之上
- 如果中途已做首轮查新，`02` 还必须吸收该检索的压力点和建议方向
- `03` 必须引用并吸收 `01` 和 `02` 暴露的问题，以及首轮查新引出的未解区分点
- 导出 `.docx` 时，`01` 到 `03` 的口径必须一致

# Stage 02: 技术交底逻辑重构与缺陷审查

## 进入条件

- 用户要做缺陷审查
- 用户要检查撰写风险、参数缺失、支撑不足、术语不一致

## 核心任务

- 提取最小可保护方案
- 检查逻辑链条、参数、结构关系、效果支撑
- 指出功能性表述、结果性表述和实施细节缺失
- 解释每个问题为什么会影响后续撰写或审查
- 如果已经做过首轮查新，结合最近现有技术压力判断哪些路线应保留、收窄或放弃

## 输出要求

- 结果写入 `02_技术交底逻辑重构与缺陷审查报告.md`
- 问题按严重程度组织
- 优先写技术路线、支撑和清楚性问题，再写普通表述问题
- 如果用了首轮查新结果，要明确区分 `交底缺陷` 和 `现有技术压力导致的重构建议`
